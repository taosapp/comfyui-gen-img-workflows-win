## 0. 三条结论先看

1. **约 36GB 里 35GB 是模型**（视频模型 26.9GB 已于 2026-10-15 移除，原为 42GB）→ 模型永远不进 git、也不适合塞进仓库；换机靠**拷贝**或**重新下载**。
2. **这个根目录现在既是仓库又是运行环境**：`origin = https://github.com/taosapp/comfyui-img2img-workflows-nvidia-windows.git`，
   上游 ComfyUI 运行时由 `scripts/prepare.py` 浅克隆进来（不保留上游 `.git`）。能这样做的前提是
   `.gitignore` 用**白名单模式**（`/*` 先全部忽略，再逐项放行策划资产），所以几十 GB 模型目录不会把
   `git status` 变成灾难。详见 3.3 / 3.4。
3. 真正需要你自己保管的是这 4 类东西（加起来不到 1MB）：

   | 类别 | 路径 |
   |---|---|
   | 工作流 | `workflows/*.json` |
   | 风格库 | `styles/*.txt` |
   | 自建节点 | `custom_nodes/comfyui-style-prompt/` |
   | 补丁 | `patches/`（本机给 ComfyUI-GGUF 打的 Qwen 架构补丁） |

## 2. 换机注意事项

### 2.1 启动脚本（已改自定位，换机基本不用动）

`start_comfyui.bat` 现在**不含任何写死路径**：

- ComfyUI 目录 = 脚本自身所在目录（`%~dp0`），换盘符 / 换用户名都无所谓
- conda 位置自动探测，顺序为：`CONDA_EXE` → PATH 里的 `conda.bat` → 常见安装位置扫描
  （`%USERPROFILE%\miniconda3`、`%LOCALAPPDATA%\miniconda3`、`%ProgramData%\Miniconda3`、
  `C:\miniconda3` 等）。本机 conda 不在 PATH，走的正是第三条
- 解释器优先级：**conda 环境 → 项目内 `venv`/`.venv` → 明确报错退出**。
  故意不拿"PATH 里随便一个 python"兜底 —— ComfyUI 依赖太重，那样只会用一堆 ImportError 掩盖真问题

```
start_comfyui.bat                默认用 conda 环境 comfyui
start_comfyui.bat 别的环境名      临时换一个 conda 环境
```

想改默认值不必动脚本，设系统环境变量即可：`CONDA_ENV`、`COMFY_ARGS`、`HF_ENDPOINT`。

**维护须知**：`.bat` 必须是 **GBK(936)** 编码，中文提示才不会乱码。
改内容请走这条链，不要直接编辑 `.bat`：

```
编辑 scripts/launcher/start_comfyui.src.txt（UTF-8）
  → python scripts/launcher/rebuild.py      # 重建根目录 .bat
  → python scripts/launcher/selftest.py     # 自检（9 项，不启动 ComfyUI）
```

两个已经踩过的坑，别再犯：

| 坑 | 症状 |
|---|---|
| 把含中文的脚本存成 UTF-8 | 双击后提示信息全是乱码 |
| `if (...)` 括号块内的 `echo` 写了半角括号（如 `1) 安装 xxx`） | 提前闭合括号块 → `安装 was unexpected at this time.`，脚本直接中断 |

换机后自检没过时的排查顺序：

1. `conda env list` 看新机上的环境名，用 `start_comfyui.bat 环境名` 指定
2. 新机没建过环境：`conda create -n comfyui python=3.12` 然后 `pip install -r requirements.txt`
3. **不要拷** `venv/`、conda 环境本身或 `site-packages` —— 二进制包与系统绑定，跨机必坏

mac 用 `start_comfyui_mac.sh`（自动找 `venv` 或 `python3`，无需修改）。

mac / Linux 直接用同目录的 **`start_comfyui_mac.sh`**（已做自定位，无需改）：

```bash
chmod +x start_comfyui_mac.sh
./start_comfyui_mac.sh                    # 默认参数
./start_comfyui_mac.sh --lowvram          # 需要时自己加参数
```

### 2.2 Python 环境

- 本机其实是**两套可用环境**，都装了 torch 2.14.0+cu126：
  | 环境 | Python | 说明 |
  |---|---|---|
  | conda env `comfyui` | 3.12.14 | `start_comfyui.bat` 走的是这个 |
  | 系统 `C:\Python314\python.exe` | 3.14.7 | **当前正在运行的实例实际用的是这个** |
- 新机上**不要拷贝** `venv/`、conda 环境、`site-packages` —— 二进制包跟系统绑定，跨机必坏。重新装：
  ```bash
  python -m venv venv && source venv/bin/activate     # mac/Linux
  pip install -r requirements.txt
  pip install -r custom_nodes/ComfyUI-GGUF/requirements.txt   # gguf / sentencepiece / protobuf
  ```
- mac 上装了 torch 之后确认 MPS 可用：`python -c "import torch;print(torch.backends.mps.is_available())"`
- ⚠️ **`custom_nodes/ComfyUI-GGUF/` 不要在新机重新 `git clone`**，否则会丢掉补丁。要么直接拷目录，要么重新 clone 后按 `patches/README.md` 打补丁 —— **不打补丁，Qwen-Image 工作流会直接报 `Unknown model architecture!`**。

### 2.3 显存 / 内存不同 → 启动参数怎么选

| 新机显卡 | 建议启动参数 | 说明 |
|---|---|---|
| 8 GB | `--lowvram`，可能还要 `--novram` | 建议换更小量化（Q4/Q3）的 GGUF，Q5 可能爆 |
| 12 GB（本机） | `--lowvram` | 现状；图片工作流 576×1024 / 8 步 + Turbo LoRA 约 36~60 秒 |
| 16–24 GB | `--normalvram` 或默认 | 会明显快，可考虑去掉 `--lowvram` |
| Apple Silicon | **不要传 `--lowvram`** | 见 2.4 |

内存（系统 RAM）比显存更关键：此前 H3 视频全套 25.7GB 权重曾把 32GB 内存压到 free 仅 1–4GB，该模型已于 2026-10-15 移除，图片工作流下 32GB 内存无压力。

### 2.4 macOS / M4 Pro 专项（重点看这段）

| 事项 | 结论 |
|---|---|
| 统一内存 | Mac 的"显存"和内存是同一个池子。图片工作流最大一套（分层文生图）。视频 H3 那套 25.7GB 权重已于 2026-10-15 删除，不再参与评估 |
| 启动参数 | **不要用 `--lowvram`**（MPS 下这个是反效果）。用默认，必要时 `--highvram`。脚本已自动设 `PYTORCH_ENABLE_MPS_FALLBACK=1`，避免 MPS 不支持的算子直接崩 |
| 量化算子风险 | 图片工作流用的 `qwen3vl_8b_int8_convrot.safetensors` 也是 **int8 convrot** 量化，这类实现可能带 CUDA 专用路径 → **在 MPS 上能否加载必须实测**；不行就换官方 BF16 文本编码器。（原 H3 视频 VAE 的同类风险随模型删除一并消失） |
| 速度预期 | M4 Pro GPU 大致相当于 3060 同档或略低，且 GGUF 反量化在 MPS 上效率不如 CUDA。图片工作流（576×1024 / 8 步 + Turbo LoRA）在 3060 上约 36~60 秒，Mac 上预计更慢 |
| 网络 | 脚本已设 `HF_ENDPOINT=https://hf-mirror.com`；如果 Mac 在公司代理后，注意 `127.0.0.1` 要绕过代理 |
| 备选 | 已无本地视频生成需求（工作流与模型均已移除）；如日后再要，优先考虑云端 API |

### 2.5 其他容易踩的点

- **`LoadImage` 只认 `input/` 目录里的文件名**，绝对路径会被路径穿越检查拒掉。工作流里存的是 `1.jpg` 这种相对名，换机后把素材图拖进 `input/` 或用界面上传，名字对不上就报 `Invalid file path`。
- **`custom_nodes/comfyui-style-prompt/` 是自定义节点，改代码必须重启 ComfyUI**；只改 `styles/*.txt` 内容不用重启，**新增**风格文件要浏览器 F5。
- 模型目录如果不想拷进项目，可以复制 `extra_model_paths.yaml.example` 为 `extra_model_paths.yaml`，把 `models/` 指向别的盘/已有的 ComfyUI 安装 —— 这样两台机器可以共用一份 36GB 模型（但别同时跑）。
- 换机后第一次跑任何工作流前，先在 `http://127.0.0.1:8188` 打开对应 json **看一眼有没有红框/缺节点**，缺节点基本就是：自定义节点没拷过去，或改完没重启。

### 2.6 整目录拷到另一台机器（本次场景）

根目录 **约 36GB**，其中 35GB 是模型。用 robocopy 并排除掉不该扩散/不需要的部分：

```bat
robocopy D:\ai\comfyui-img2img-workflows-nvidia-windows E:\ComfyUI /E /XD .git output temp __pycache__ .workbuddy input agent-kit docs /XF *.log
```

（`/E` 拷贝子目录含空目录，不会删除目标已有文件；网络/移动硬盘同理，把目标换成对应路径。）

| 排除项 | 理由 |
|---|---|
| `input/` | 真实可识别公众人物的照片，没必要跟着走 |
| `output/` | 生成产物，含涉真人合成结果，不该扩散 |
| `.git/` | 官方 clone 的历史，新机上基本用不到 |
| `.workbuddy/` | 本机内部记录，含个人路径（记忆快照已在 `agent-kit/memory/` 里，排掉不影响） |
| `temp/`、`__pycache__/`、`*.log` | 缓存与日志，新机自动重建 |

> ⚠️ **`agent-kit/` 千万不要排除**（清单里没有它，默认会跟着走）。它是技能与记忆的唯一载体，
> 被排掉的话新机上的 AI 助手就完全不了解这个项目的来龙去脉了。

- **要真跑生成，模型必须一起带**（分包体积见 1.2）；一个都不带也能启动，
  只是打开工作流会提示模型缺失，属预期。
- 拷完在目标机按顺序做四件事：① 跑 `agent-kit` 装回技能与记忆（见 1.1 说明）② 双击
  `start_comfyui.bat` ③ 按 2.3 决定要不要 `--lowvram` ④ 按 2.5 打开工作流看有没有红框。

## 3. 发布成开源项目

### 3.1 当前做法：仓库与运行时同目录（白名单）

已经在跑了，不用重建：`.gitignore` 先 `/*` 忽略根目录所有东西，再 `!` 逐项放行
`workflows/`、`styles/`、`custom_nodes/comfyui-style-prompt/`、`patches/`、`scripts/`、`docs/`、
两个启动器与 `README.md` / `LICENSE` / `.gitignore` / `.gitattributes`。新机直接：

```bash
git clone https://github.com/taosapp/comfyui-img2img-workflows-nvidia-windows.git
cd comfyui-img2img-workflows-nvidia-windows
python scripts/prepare.py          # 补齐运行时 / 依赖 / 节点补丁 / 模型
```

**备选：另建一个只装资产的仓库**（不想让仓库跟 36GB 模型同目录时才需要）：

```bash
SRC=/d/ai/comfyui-img2img-workflows-nvidia-windows     # 本机项目根目录

```

### 3.2 该提交的文件清单

| 提交 | 说明 |
|---|---|
| `workflows/*.json` | 工作流本体（不含模型，文件只有几十 KB） |

**关于 `patches/`**：本机的 `custom_nodes/ComfyUI-GGUF` 是 `city96/ComfyUI-GGUF` 的 clone（提交 `6ea2651e`，2026-01-12），本地改了 `tools/convert.py` 加了一个 `ModelQwenImage` 架构类。之所以必须打这个补丁：`qwen-image-2.1-Q5_K_M.gguf` **没有任何元数据**，加载器 `loader.py:101` 会用 `detect_arch()` 从张量名反推架构，没这个类就会抛 `Unknown model architecture!`。
所以仓库里**提交补丁文件 + 说明**，而不是把整个 ComfyUI-GGUF 目录拷进去。

```gitignore
# 系统文件
Thumbs.db
.DS_Store
```

> 关键一行是 `/*`：根目录所有东西先当不存在，再一条条 `!` 放行。这样 `models/`（35GB）、`input/`、
> `output/`、`user/`、上游运行时代码全部默认不会误提交，也不需要记得维护排除名单。
> 代价是新增一类资产时要手动加一行 `!`，忘了就会静悄悄漏文件 —— 提交后用 `git status --short` 确认。
> 另：上游 ComfyUI 的 `.gitignore` 里有 `/custom_nodes/`，所以**先写上自己这份再 clone 运行时**，
> 不然自己写的节点包会被忽略。

| 内容 | 你的权利 | 建议 |
|---|---|---|

README 里建议写清的三件事：① 模型下载表（文件名 + 放置目录 + 出处）；② 需要哪些第三方节点；③ 用途声明（别把生成内容的责任揽到自己身上）。

### 3.6 跨平台：不要分两个分支

**结论：单分支。** macOS 不用 CUDA 确实差别大，但差别落在**运行方式**上，不落在**代码内容**上。实测依据：

| 检查项 | 实测结果 |
| --- | --- |
| 自建节点包里的 `cuda` / `mps` / `torch` 引用 | **0 处**；无 `requirements.txt`，纯标准库 |
| `workflows/*.json` 用到的节点类型 | 43 种，**无任何 CUDA 专有节点** |
| 官方 `requirements.txt` | 只有 `torch` / `torchsde` / `torchvision`，无 `xformers` / `triton` / `nvidia-*` |
| 两个启动脚本的差异 | 仅启动参数：`--lowvram` vs 不传 + `PYTORCH_ENABLE_MPS_FALLBACK` |

所以平台差异只影响最外层那两个脚本文件；而 `workflows/` + `styles/` + 自建节点 + `patches/`（占项目资产 95% 以上）是**逐字节平台无关**的。分两个分支等于把它们维护两份，且漂移是**静默的**——在 Windows 分支改一条风格提示词，Mac 分支永远落后，没有任何机制会提醒你。

**取代分支的四件工具：**

| 差异类型 | 用什么表达 | 本项目现状 |
| --- | --- | --- |
| 启动方式 | 各平台一份自定位脚本 | 已有 `start_comfyui.bat` / `start_comfyui_mac.sh` |
| 运行参数 | 脚本内平台判断 + 环境变量覆盖 | Mac 脚本已自动设 `MPS_FALLBACK`、默认不传 `--lowvram`，要加参数直接往后接 |
| 功能子集（哪些能跑） | README 里的「平台能力矩阵」表 | 见下 |
| 模型 / 工作流变体 | 文件名或目录后缀（如 `*-mac.json`），而非改代码 | 待 Mac 实测后再定 |

**判据（以后照这个问）**：只有当**同一份文件**在两个平台上必须内容不同、且无法用 `if sys.platform` 包住（典型：CUDA 扩展、triton kernel 这类编译期绑定），才谈得上分叉。本项目目前 **0 个**这样的文件。

**唯一可能逼出分叉的点**：`int8_convrot` 量化算子在 MPS 上的兼容性**尚未实测**。视频那处（`minimax_h3_video_vae_int8_convrot`）已随模型删除消失，现在只剩一处：

- `qwen3vl_8b_int8_convrot.safetensors` → **图片风格转换 / 彩墨**的文本编码器

所以 Mac 上实测的第一件事就是让它加载一次，而不是先跑工作流。即使真不兼容，解法也**不是分代码分支**：换一份非量化权重（bf16 safetensors）+ 加一份工作流变体，Python 代码仍然共用。

**平台能力矩阵（写进 README）：**

| 工作流 | CUDA（12GB+） | Apple Silicon |
| --- | --- | --- |
| 图片风格转换（极速版） | 可用（实测，36~60 秒/张） | 未实测 —— 依赖 `qwen3vl_8b_int8_convrot` 能否在 MPS 加载 |
| 中国彩墨图生图（质量版/极速版） | 可用（实测） | 同上 |
| 分层文生图 / 抠图 | 可用 | 未实测 |
| ~~H3 图生视频 768p~~ | ~~可用（实测）~~ | 2026-10-15 模型与工作流已移除 |
